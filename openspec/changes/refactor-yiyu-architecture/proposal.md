# Proposal

## Why

现有修复改善了部分可靠性，但后端的命令、会话、持久化和系统能力仍耦合在少数大模块中；前端各窗口虽然已经更换材质，信息层级和细节仍不够统一，尤其快捷浮窗未达到预期。需要按可验证、可回退的阶段重构，而不是继续累积局部补丁。

## What Changes

- 重新划分桌面适配、翻译会话、服务与持久化的职责，保持现有 IPC、配置、历史和密钥兼容。
- 统一主窗口、浮窗、设置、首次配置与应用内弹层的排版、控件和状态；先重做快捷浮窗，再逐窗检查。
- 用现有测试、模拟服务、截图及真实系统操作覆盖关键路径，分别记录自动化覆盖和仍需真机验收的部分。
- 保持变更可逐阶段回退；不更换存储格式或引入新的框架与多余服务。

## Capabilities

### New Capabilities

无。本次不新增产品能力；沿用 `add-yiyu-desktop-translator` 与 `redesign-yiyu-frontend` 中尚未归档的现有行为和外观规格。两者尚未归档，`openspec/specs/` 为空；本变更声明 `skip_specs`，不复制或虚构规格。

### Modified Capabilities

无。本次不改变已归档规格，也不取消现有能力。浮窗视觉与验收继续由 `redesign-yiyu-frontend` 负责。

## Impact

- `src-tauri/src/` 的命令、会话、系统接口、更新与凭据适配；`crates/yiyu-core/` 中的翻译、设置和历史服务。
- `web/src/` 的窗口、状态、组件与样式，及 `web/qa/` 中的行为和视觉回归。
- 不改变应用标识、现有设置、数据库、系统凭据标识、快捷键或用户背景；macOS 签名和系统权限保持现有路径。
